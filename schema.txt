================================================================================
SentriQ Database Schema
================================================================================
Project ref: pwomrtwoihtulautvjwv
Backend: PostgreSQL (via hosted API)
Auth: Email/password (auth.users)
Storage: medical-records, dog-images, health-reports buckets
Live sensors: Realtime device telemetry keyed by device_id (external RTDB)
RLS: all tables USING (true) WITH CHECK (true) for authenticated
================================================================================

================================================================================
HELPER FUNCTIONS
================================================================================
- handle_new_user()         : trigger on auth.users → insert profiles
- set_updated_at()          : BEFORE UPDATE trigger on tables with updated_at
- sync_ngo_dogs_count()     : AFTER INSERT/DELETE/UPDATE on dogs
- sync_post_likes_count()   : AFTER INSERT/DELETE on community_likes
- sync_post_comments_count(): AFTER INSERT/DELETE on community_comments
- is_ngo_member(ngo_id)     : SECURITY DEFINER helper for RLS
- user_ngo_ids()            : returns ngo ids for current user

================================================================================
ROW LEVEL SECURITY (summary)
================================================================================
- profiles: users can read all (for community), update own row
- ngos: authenticated read; members can update; owner can delete; anyone authenticated can insert (create NGO)
- ngo_members: members of same NGO can read; owners/admins manage
- dogs / dog_alerts / vital_readings / medical_records / medical_history / health_reports:
  accessible only to ngo_members of that dog's NGO
- community_posts/comments/likes: authenticated read; authors manage own
- chat_conversations/messages: owner only

================================================================================
STORAGE BUCKETS
================================================================================
- medical-records  (private)  path: {ngo_id}/{dog_id}/{filename}
- dog-images       (public)   path: {ngo_id}/{dog_id}/{filename}
- health-reports   (private)  path: {ngo_id}/{dog_id}/{filename}

================================================================================
DATA FLOW
================================================================================
1. Signup → auth.users → profiles trigger → create ngo → ngo_members (owner)
2. Add dog → dogs table with device_id
3. Live vitals → external RTDB /dogs keyed by device_id → UI maps dog.device_id
4. Optional: client/periodic job writes vital_readings snapshots for history/PDF
5. Alerts → dog_alerts + dogs.has_alert / status for red signal on dashboard
6. Medical files → Storage + medical_records (+ medical_history for AI)
7. Chatbot → loads medical_history + recent vitals/alerts as context
8. PDF reports → client generate + optional health_reports row + Storage upload
